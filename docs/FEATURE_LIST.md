## V1.1（MVP 之后快速迭代）

- [x] **网址截图兜底方案**：新增独立后端服务 `server/`（Node + Express + Playwright）。提交网址后先由后端读一次目标网址的响应头（`X-Frame-Options`/CSP `frame-ancestors`）判断是否会拒绝嵌入，会拒绝就直接跳过 iframe、走截图模式；否则仍按原逻辑尝试 iframe，10 秒超时兜底不变。实测发现单靠 iframe 超时判断不可靠——被拒绝嵌入的网站，浏览器通常几百毫秒内就会触发 iframe 的 `load` 事件（空白内容也算"加载完成"），等不到超时，因此补了这道响应头预检。截图接口本身有内存缓存（10 分钟 TTL）+ 同 URL 并发去重 + 全局并发上限（3）做基础的成本/滥用控制；预检和截图都做了基础 SSRF 防护（拦截 localhost/内网网段/file 协议等，DNS 解析后再校验一次）。前端通过 Vite `server.proxy` 把 `/api` 转发到后端 3001 端口，保持单域名访问。已用 curl + 自动化浏览器脚本做端到端验证（含 Fit/Fill、内外屏切换、和普通网址走 iframe 的回归测试）。详见 `PRD.md` 4.1/6.3/6.4 节与 `TECH_SPEC.md`。
